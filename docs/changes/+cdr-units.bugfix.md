`compute_cdr_metrics` (and so `ROMSOutput.cdr_metrics` and `UpscaledCDR`) now checks the units of every variable it reads against an explicit contract and converts amount prefixes, instead of reading only the amount prefix of `FG_CO2` and `hDIC`.
* The efficiencies were the ratio of uptake and source in their native units, so output whose fluxes, inventories and sources used different prefixes (e.g. `FG_CO2` in `mol/m^2/s`, `DIC_source` in `umol/s`) gave efficiencies wrong by powers of ten; the inventory difference subtracted `hDIC_ALT_CO2` in its own units. Each variable is now converted (mol, mmol, umol, nmol; eq, meq, ueq, neq).
* Units with other dimensions raise a `ValueError` naming the variable: mass-normalised units such as `umol/kg`, concentrations where an inventory is expected, CGS units (`nmol/cm^2/s`, which previously gave an uptake 100 times too large), and time units other than seconds. Previously unrecognised units were taken as mmol with a warning.
* Output written by ucla-roms (`mmol/m^2/s`, `meters mmol/m^3`, `meq/s`, `mmol/s`) and missing units give the same results as before.
* Unit symbols are case-sensitive, as in UDUNITS: `Mmol/m^2/s` (megamole) is refused rather than read as mmol. `mMol`, which ucla-roms writes for its passive and CDR tracers, is accepted as mmol.
